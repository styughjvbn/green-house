# 향후 확장 계획

2026-10-28 기준. 저장소의 구현·기능 문서를 기준으로 완료 범위와 후속 과제를 구분한다. 구현 완료는 운영 배포·인증·복원 검증까지 완료됐다는 뜻이 아니다. 아래 우선순위는 다음 작업을 선택하기 위한 기준이며 보류 기능의 재개 승인은 아니다.

사진 자동 입력은 2026-10-28 사용자 확인으로 **운영 적용 완료**다. 운영 성능 측정과 DB·사진 복원 검증은 별도 후속 과제로 유지한다.

## 1. 우선순위 높음

### 사진 자동 입력의 운영 안정화

- 운영 적용을 마친 사진 자동 입력의 실패 사례와 사용자 확인·수정 부담을 수집해 후속 개선 순서를 정한다.
- 실제 운영 PC에서 전처리 동시 처리 수에 따른 완료 시간·최대 메모리·거절·취소 동작을 확인한다. 개발 PC 측정값으로 운영 워커 수를 확정하지 않는다.
- 모델·추출 프롬프트 변경 시 품종 ID 연결, 거래처 기본 연결, 숫자 검산, 확인 필요 표시가 유지되는지 검증한다.
- 실패·중지·일부 묶음 완료 후 재시도에서 완료한 결과를 보존하고 중복 등록하지 않는지 점검한다.
- AI는 입력 초안만 제공하며, 저장·재고 반영은 사용자 검토 후 기존 Sales 유스케이스에서 처리한다.

### 전처리 품질과 인식 평가

- 기존 실사진의 정답을 검수하고 문서 수뿐 아니라 제목·거래처·날짜·마지막 품목 보존을 회귀 기준으로 삼는다.
- 그림자로 인한 표 누락, 자동 회전 오판, 헤더 잘림, 흐린 세로선으로 인한 양식 미확인을 우선 추적한다.
- 문서 보존 실패를 제외한 인식 점수와 전체 입력의 실패율을 별도로 기록한다. 모델 자체 신뢰도를 실제 정확도로 취급하지 않는다.
- 리사이즈·전처리 순서와 해상도 재시도 기준은 실제 정답 대조로 평가한다. 기존 실험만으로 모든 사진에서 특정 순서가 우월하다고 확정하지 않는다.
- 새 예외 규칙을 늘리기 전에 기존 두 양식·잉크 비율 정책과 수동 영역 수정으로 해결 가능한지 확인한다.

### DB·사진 백업과 복원 확인

- 기존 운영 백업의 `db/`와 새 스크립트의 `database/` 경로, 실제 스케줄 호출 대상을 확인하고 하나의 운영 절차로 맞춘다.
- DB dump와 사진 파일을 함께 복원해 참조 키·크기·해시와 인증된 사진 조회를 확인한다.
- 공유 사진과 교체 이력(`replaced/`)의 보존·용량 점검 정책을 정한다. 과거 DB dump가 참조하는 파일을 날짜만 보고 삭제하지 않는다.
- Codex 인증 PVC의 재시작 후 유지와 재인증 절차를 확인한다. PVC 영속성을 별도 백업으로 간주하지 않는다.

## 2. 중간 우선순위

### 작업·재고 운영 UX

- 작업 대상 새로고침의 시점·권한·기존 대상 스냅샷 보존 정책을 정한 뒤 구현한다.
- 기존 취소 영향 범위를 농장 배치 위에 표시하는 시각화를 검토한다. 취소 판단 로직을 프론트에서 다시 만들지 않는다.
- 기존 대사·제약 검증을 운영 절차로 유지하고, 불일치 확인·원인 추적 화면을 검토한다. 원장·스냅샷을 새로 도입하는 과제로 다루지 않는다.
- 작업 유형 설정과 보정 안내는 실제 현장 사용에서 불편이 확인된 부분부터 개선한다.

### 사진 조회와 저장소 운영

- 목록·상세 사진 전환의 실제 지연을 측정한 뒤 썸네일·바이너리 전달·캐시를 검토한다.
- 저장 용량·복원 시간·다중 인스턴스 요구가 생기면 기존 저장소 port에 S3 adapter를 추가한다. 현재 로컬 저장소를 즉시 교체하는 일정은 확정하지 않는다.
- 사진 정리는 DB 참조와 보존 중인 백업의 참조를 함께 고려한다. 일반 사용자 삭제와 운영 고아 파일 정리를 구분한다.

### 데이터 가져오기

사진 첨부·내용 인식·검토 후 등록은 구현 완료다. 아래는 별도 후속 범위다.

- 엑셀/CSV 가져오기와 원본 행 보존.
- 가져오기 전 검수 상태·중복·누락 탐지.
- 기존 품종·거래처 식별자 연결과 재시도 시 중복 생성 방지.

### 배치 정밀화·분석

- 논리 구역 병합/분할과 세그먼트별 수용량 관리.
- 판 단위·행잉·임시 배치의 현장 요구를 확인한 뒤 배치 경고 개선.
- 경매장별 유찰률/반환률, 구역별 사용률·작업 누락, 상태 이상 기간 분석.

## 3. 장기 확장

### 현장 기록과 모바일

- 난 묶음 사진 기록과 작업 이력 연결.
- 고가품·모주 등 필요한 대상부터 개체·QR 관리.
- 모바일 현장 동선 개선, QR 스캔·음성 메모·오프라인 임시 저장.
- 기존 PC·태블릿 입력을 유지하며 별도 모바일 UI의 필요성을 먼저 확인한다.

### AI 업무 확장·외부 연동

- 현재 조회 도구 기반을 활용한 농장 데이터 조회·분석과 작업 계획 미리보기.
- 변경 도구는 실행 권한·사용자 승인·멱등성·감사와 기존 업무 트랜잭션을 보장할 수 있을 때 별도로 설계한다.
- 온도/습도/광량/CO₂ 센서, 병해충 의심 사진 분류, 작업 추천·출하 가능 수량 예측.
- 회계·택배·판매 채널 연동은 실제 운영 수요가 확인된 뒤 검토한다.

## 4. 보류 또는 신중 검토

다음 기능은 바로 구현하지 않는다.

- 정밀 CAD 수준의 좌표 편집과 개별 화분 전수 관리.
- 외부 주문 또는 전표 작성만으로 출고 완료 없이 수량을 차감하는 처리.
- 자동 입금 확정과 AI 판단만으로 전표 저장·재고 변경을 실행하는 기능.
- AI 진단을 운영 판단의 단독 근거로 사용하는 기능.
- 범용 에이전트 플랫폼, 변경 도구, RAG·멀티 에이전트·MQ의 선행 도입.
- 자유 서술형 재추출 피드백의 재도입. 현재 필드 검토·영역 수정·재읽기 흐름을 유지한다.
- Codex 잔여 사용량에 따른 차단. 신뢰할 수 있는 조회 계약과 운영 필요성이 확인된 뒤 검토한다.

### 실사 수량 조정·작업 수량 정정 보류

- 실사 수량 조정과 작업 기록 수량 정정은 기본 비활성화 상태로 유지하며 운영에서 활성화하지 않는다. 기존 구현과 감사 이력은 보존한다.
- 실사는 구역·난 묶음 단위 흐름으로, 작업 수량 정정은 작업 단위 흐름으로 개편하는 정책을 확정한 뒤 재개한다. 설정 변경만으로 기존 진입점을 다시 열지 않는다.
- 작업일·상태 정정과 결과 생성 취소는 계속 허용한다. 상세 범위는 [작업 보정·실사 정책](features/work-operation-and-orchid-collection.md)과 [운영 설정](07-deployment.md)을 따른다.

### 판매: 수납·실제 환불·과거 자료 연결 보류

사용자 결정으로 다음 작업은 계속 보류한다. 별도 재개 요청 전까지 구현하지 않는다.

- Payment의 실제 금액 환불과 수납 원장·화면 연결. 현재 거래금액 조정과 실물 반품 도착 처리는 유지하며 `수납 비활성화`도 유지한다.
- 부분입금 UX 개선, 은행 입금 내역 가져오기·매칭 후보 관리·자동 매칭은 수납 화면 재개 시 범위를 다시 정한다. 기존 수납·배분 백엔드가 없다는 의미는 아니다.
- 완료 기록의 과거 난 묶음·확인된 revision 출처 연결, 미반영 재고의 차감·실사 보정 이력 연결, 과거 음수 전표 3건(#127·#134·#137)의 원판매·반품 연결과 표현 전환. 기존 자료를 보존하고 연결·재고 효과를 추정하지 않는다.

일반 판매 일부 수량 가격 조정·반품과 일반 판매/경매의 실제 도착·기록만 등록·도착 취소는 구현 완료 범위다. 과거 파생 정산 묶음·재계산은 현행 경매 대금 구조에서 제거됐으므로 기존 로드맵의 정산 재계산 이력 항목을 그대로 재추진하지 않는다. 상세 경계는 [판매 기능 문서](features/sales-auction-settlement.md#보류-유지-실제-환불과-과거-자료-연결)를 따른다.
